# 한 과제에 여러 경로 — 실험 기록

2026-09-30 ~ 10-02. 물음은 하나다. **같은 ARC 과제를 푸는 유효한 ARCLE 궤적이
여럿 나올 수 있는가, 그리고 무엇이 그걸 갈라놓는가.**

좋은 경로를 찾는 실험이 아니다. 배포 게이트는 따로 있고, 여기서 세는 것은
가짓수다. 다만 "유효"의 기준은 느슨하지 않다 — 뽑은 인스턴스를 전부 풀고,
정답을 흐트러뜨려도 같은 경로를 내놓아야 한다(`dep == 0`).

자료 전부: `/hdd_data/yunho/route-diversity/`
(`prompts/` 지시문, `results/` 측정값 JSON, `logs/` 실행 로그, `scripts/` 측정 코드)

---

## 1. 무엇을 "다른 경로"로 세는가

경로의 신원은 **(op 이름, 실제로 고른 칸의 집합)의 나열**이다. 인스턴스 5개에
대한 나열을 묶어 하나의 서명으로 쓴다.

선택을 bbox로 적었는지 칸 목록으로 적었는지는 보지 않는다. 같은 칸을 고르면
같은 선택이다. 이게 중요한 이유는 한 번 틀렸기 때문이다 — 표기를 그대로 비교해
"82%가 다른 일"이라고 셌다가, 마스크로 다시 재니 76%였다.

두 경로의 관계는 셋으로 가른다.

| | |
|---|---|
| 같음 | 단계별로 op과 고른 칸이 모두 같다 |
| 순서만 | 같은 단계들의 순서만 다르다 |
| 다른 일 | 그 밖 — 다른 op을 쓰거나 같은 op을 다른 영역에 쓴다 |

측정 코드는 `scripts/diversity_all.py`.

## 2. 출발점 (10-01)

그동안 만들어둔 maker 변형 전부(`maker/` 아래 모든 폴더)를 같은 인스턴스에
돌려 셌다.

```
과제 400,  과제당 푸는 코드 5.7개  ->  서로 다른 경로 2.7가지
경로 2가지 이상  316 / 400
경로 1가지뿐      84 / 400
기준 외 경로 692개 중  순서만 68 (10%)  다른 일 624 (90%)
```

**코드가 많다고 경로가 늘지 않는다.** 5.7개에서 2.7가지면 절반 이상이 같은
궤적이다. `arc-best`·`arc-agi1-noref` 계열은 서로 복사본이거나 같은 곳으로
수렴한다.

계열별로 "그 계열만 낸 경로"를 과제 수로 나누면 순위가 뒤집힌다.

| 계열 | 과제 | 그 계열만 낸 경로 | 과제당 |
|---|---|---|---|
| alt (대안 생성) | 23 | 33 | 1.43 |
| golf (짧게) | 25 | 33 | 1.32 |
| redo-* (지시 바꿔 재생성) | 124 | 122 | 0.98 |
| var (교란 재생성) | 128 | 116 | 0.91 |
| base (arc-best/noref) | 396 | 339 | 0.86 |
| noO (O 안 보여주고) | 33 | 5 | **0.15** |
| arc-agi-1 (배포본) | 394 | 0 | 0.00 |

`base`가 총량 1위인 것은 396개에 돌렸기 때문이다. `noO`는 다양성 목적으로
쓸 이유가 없다.

## 3. 네 가지 지시 (10-01 ~ 10-02)

지시문 전문은 `prompts/INSTRUCTIONS.md`. 네 갈래 모두 가드 두 문장을 공유한다.

> Every selection must be something you can name from the input before you know
> the answer — a rectangle, a connected object, all cells of one colour, a row,
> a column, the cells a copy lands on.
>
> And the operations must be derivable from the input grid and the worked
> examples alone: handed a different answer grid, this function must return the
> same operations.

가드가 없으면 답을 읽는다. 가드를 뺀 `golf2`는 25개 중 2개가 `dep 1.00`
(정답을 흐트러뜨리면 경로가 통째로 바뀜)이었고, 가드를 넣은 갈래는
**137개 maker 중 0개**였다.

### 3.1 짧게 (`golf84`, 84개)

이미 푸는 maker를 보여주고 "같은 일을 더 큰 획으로, 더 적은 동작으로".

```
생성 84/84,  인스턴스를 다 푸는 것 78,  새 경로 36  (46%)
경로 1가지 -> 2가지 이상  40 / 84
```

25개 표본에서는 23/25(92%)였는데 84개에서 46%로 떨어졌다. 표본 25개는 이미
경로가 여럿이던 과제였고, 84개는 **어떤 지시로도 안 갈라진 과제**다.

### 3.2 재표집 (`resample1`, 400개)

참조도 피드백도 없이 같은 프롬프트를 다시 뽑는다. 준비 비용 0.

```
과제 400,  그 갈래만 낸 경로 129,  과제당 0.38
```

### 3.3 남의 풀이 참조 (`barc1`, 160개)

[BARC](https://github.com/xu3kev/BARC) seed를 참조로 붙였다. seed 160개가
우리 400개와 **전부** 겹친다. `generate_input()`은 떼어냈다 — 인스턴스는
RE-ARC generator에서 나오고, seed의 생성기를 보여주면 베낄 이유가 생긴다.

> That is one person's reading of this task, written in their own vocabulary
> rather than ARCLE's. Where it carves the problem differently from the maker
> above — different objects, a different order, a different thing held fixed —
> follow the reading in the reference, not the one already here.

```
과제 160,  그 갈래만 낸 경로 67,  과제당 0.47  (네 갈래 중 최고)
```

과제당 수율은 가장 높지만 seed가 있는 160개에만 쓸 수 있다.

### 3.4 다르게 묶기 (`group1`/`group2`/`group3`)

앞 세 갈래가 전부 실패한 41개를 보고 세운 가설: 막혀 있는 것은 어휘도 길이도
아니고 **무엇을 한 단위로 보는가**다.

> What must change is the unit of work. Look at what this route treats as one
> thing — one object, one cell, one row, the whole grid — and write the same
> rule against a different unit. (...) A longer route is fine. What is not fine
> is the same decomposition written again — if you cannot see a second way to
> carve this task, say so plainly instead of renaming variables.

| | 대상 | 다 푼 것 | 새 경로 | |
|---|---|---|---|---|
| `group1` | 41 (경로 1가지) | 38 | **35** | 92% |
| `group2` | 105 (경로 2가지) | 98 | **85** | 87% |
| `group3` | 254 (경로 3가지 이상) | 진행 중 | | |

**네 갈래 중 가장 생산적이다.** 다른 셋이 전부 실패한 과제에서 92%,
이미 경로가 둘인 과제에서도 87%로 포화 기미가 없다.

마지막 문장("두 번째로 자를 방법이 안 보이면 그렇다고 말하라")이 실제로
작동했다. `d10ecb37`의 생성 코드에 이렇게 적혀 있다.

```
# I found no second non-redundant way to split this task. Every crop is anchored at ...
```

규칙이 "입력의 좌상단 2×2를 남긴다"이고 2×2가 과제 고정 상수라 자를 단위가
하나뿐이다. **진짜 외길로 확인된 유일한 과제다.**

## 4. LLM 없이 — 기계적 변환

기존 경로를 변형해 새 경로를 만들 수 있는지. 유효 판정은 추측이 아니라
ARCLE 재생이다. 코드는 `scripts/mech.py`, `scripts/mechroutes.py`.

| 변환 | 유효 | 기존 경로와 **다른** 과제 |
|---|---|---|
| 순열 (겹치지 않는 이웃 두 단계 자리 바꾸기) | 18235/19403 (94%) | — (세지 않음) |
| 분할 (떨어진 덩어리를 덩어리별 단계로) | 218/221 (99%) | **40** |
| 병합 (같은 Color 연속 두 단계를 하나로) | 500/568 (88%) | **117** |

둘 중 하나라도 새 경로를 내는 과제 **141 / 400**, 비용 0.

**순열은 세지 않는다.** 297개 과제에서 평균 61개씩 나오지만 읽는 사람에게는
같은 풀이이고, 수치만 부풀린다.

## 5. 품질 — 새 갈래가 쓸 수 있는 것인가

84개 과제에 대해 배포 게이트 전수 채점 (`results/newarms.json`).

| arm | maker | 배포 기준 전부 통과 | `dep > 0` |
|---|---|---|---|
| `arc-agi-1` (배포본) | 84 | 84 | 0 |
| `golf84` | 84 | 83 | **0** |
| `resample1` | 84 | 83 | **0** |
| `barc1` | 29 | 27 | **0** |

**답을 읽는 maker가 하나도 없다.** 떨어진 것은 `solve` 각 1개와 `zero` 각
1개뿐이다.

임의 마스크(선택이 자기 bbox의 진부분집합인 비율)는 따로 쟀다.

| arm | 평균 임의 마스크 | 마스크가 0.25 넘게 나빠진 과제 | 어휘가 바뀐 과제 |
|---|---|---|---|
| `arc-agi-1` | 10% | — | — |
| `golf84` | 22% | 20 | 14 |
| `resample1` | 16% | 8 | 16 |
| `barc1` | 15% | 2 | 6 (29개 중) |

**이 축은 기각 사유가 아니다.** 임의 마스크가 뜻하는 것은 "궤적 밖에서 한
계산"이지 "답을 읽었다"가 아니다(그건 `dep`가 본다). 다양성 재료로는 무관하고,
이 중 하나를 배포본으로 승격할 때만 다시 보는 값이다 — 승격 게이트에는 이미
들어 있다.

다만 경향은 분명하다. **짧게 만들라는 지시는 마스크로 값을 치른다.**
`golf84`는 어휘 14개를 바꾸면서 마스크를 20개 과제에서 악화시켰고,
`resample1`은 어휘 16개를 바꾸면서 8개만 악화시켰다.

## 7. 밟은 것

측정 쪽에서 네 번 틀렸고, 네 번 다 실제 데이터에 대보고서야 알았다. 기록해
두는 이유는 같은 모양의 실수를 또 하기 때문이다.

| 틀린 측정 | 무엇을 재고 있었나 | 어떻게 드러났나 |
|---|---|---|
| 출력 격자를 입력 크기로 잘랐다 | 패딩값 10을 색으로 셈 | 결함 1개가 106개로 부풀었다 |
| 배경 = 최빈색 | 3×3에서 모양색이 0보다 많으면 뒤집힘 | 111개 중 대부분이 거짓 |
| hold 기록 전체 = 역할 | 31aa019c는 per-cell 색 수백 개 | 54개 중 10개만 진짜 |
| 유지된 색 중 1등 = 그 색의 역할 | 빈도는 인스턴스마다 변함 | 671개 전부 오검출 |

공통점은 **쉽게 셀 수 있는 대용물을 재고 그걸 묻고 싶었던 것이라 불렀다**는
점이다. 숫자가 크게 나오면 대용물을 의심하는 편이 맞았다.

운영 쪽에서도 둘 밟았다.

- 큐가 `/usage`의 **주간만 보고 세션은 안 봤다.** 세션이 차자 호출이 즉시
  실패했고, 루프가 그걸 "실패한 라운드"로 세서 재시도 6번을 2분 만에 태우고
  죽었다. 이제 세션도 보고, 5분 안에 끝났는데 maker가 안 늘면 한도에 막힌
  것으로 보고 재시도로 세지 않는다.
- 변환 함수가 **원래 순서를 후보 목록 맨 뒤에 두어** 이미 멀쩡한 에피소드도
  재배치했다. 결함 26개를 고치면서 나머지 5972개를 조용히 다시 쓸 뻔했다.

## 8. 남은 것

- **6개 과제가 아직 경로 1가지.** 그중 `d10ecb37`은 모델이 외길이라고 명시했고,
  `5daaa586`·`ce602527`은 **코드는 다시 썼는데 궤적이 같다**(유사도 0.53, 0.70).
  ARCLE op 어휘가 좁아 "다르게 생각한 것"이 "다르게 실행한 것"으로 항상
  이어지지는 않는다. 나머지 3개는 새 분해를 시도했다가 인스턴스를 못 맞춘
  정확도 실패다.
- **인스턴스 5개 기준.** 15개로 올리면 "다 푸는 코드"가 줄어 경로 가짓수도
  줄 수 있다. 지금 수치는 상한에 가깝다. LLM은 안 든다.
- **"다른 일"의 폭을 안 쟀다.** 물체를 다르게 묶은 것과 완전히 다른 개념으로
  푼 것이 한 칸에 들어가 있다.
- 분할·병합을 전수로 적용하면 141개 과제에 경로를 하나씩 더 붙일 수 있다.
  아직 maker로 만들어 넣지는 않았다.
